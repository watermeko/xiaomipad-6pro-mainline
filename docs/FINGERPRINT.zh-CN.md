# 小米平板 6 Pro 指纹使用说明

[English](FINGERPRINT.md)

## 当前状态

FPC1264 已实现 Ubuntu 设置页的原生录入接口，使用系统授权对话框，以及
fprintd/libfprint 的进度、取消和模板保存流程。正常使用不需要终端或单独的
指纹应用。

截至 2026-10-07，已在已知 256 GB 开发机完成原生设置录入，并保留模板升级到
DP＋指纹组合内核 `6.17.0-rc1-gfe81794b5e1b`、用户态 `4d6b22f`。
**已验证已录手指通过、未录手指拒绝、原生锁屏解锁，以及从平板存储正常重启后
直接用指纹进入桌面。** 系统认证结果、会话状态与用户确认相互对应。

v0.6.0 完整安装包已经整合这些组件，并完成开发机上的完整安装、首次设置与用户功能确认。

## 使用条件

v0.6.0 在首次设置后自动支持第一个普通本地账号（UID 1000），无需预先写入用户名。
范围是**该账号的一枚指纹**，必须配套准确的内核、FPC 模块、设备树及原厂固件，不能跳过
内核、模块哈希或接线检查。

临时 RAM 启动不会安装下次开机使用的内核。普通重启后要继续使用指纹，必须
持久安装配套内核和模块；上述开发机已验证这一正常启动路径。构建与安装细节见
[组件说明](../device/fingerprint/oem/README.md)。

## 从 Ubuntu 设置录入

1. 打开指定账号的**设置 → 系统 → 用户 → 指纹登录**。如果系统要求解锁设置，
   使用其正常授权对话框。
2. 选择手指，在系统密码对话框中授权录入。
3. 按原生向导的采样、抬起及调整位置提示操作，直到显示完成。取消会等待正在
   进行的操作清理后再释放传感器。

录入成功后，验证使用 Ubuntu 正常的登录和锁屏界面。普通密码登录栈保持不变，
指纹不可用时仍可使用密码。设置项出现、服务启动或传感器节点存在，都不等于
录入和解锁已经成功。

### 每个账号一枚手指，以及原因

账号里已有指纹时，再录一枚会被拒绝。桌面把这件事显示成**「Fingerprint device
storage is full」（指纹设备存储已满）**，这是错的：没有任何东西满，模板只有 772 KB。
真实原因在验证路径里。

`pam_fprintd` 让 fprintd 去验证「任意」已注册指纹，fprintd 随后只有两种做法：

| 已录指纹数 | 设备实现 `IDENTIFY` | 结果 |
|---|---|---|
| 1 | 无所谓 | 验证这一枚 |
| 2 枚以上 | 是 | 对整个 gallery 做 1:N 识别 |
| 2 枚以上 | **否** | **只验证 `gallery[0]`，第一枚** |

本 TOD 驱动没有实现 1:N 识别，因为 OEM 运行时每次采集只能匹配**一个**导出的数据库。
所以录第二枚指纹会「录入成功」，然后登录时永远匹配不上——一个只占空间还会误导人的
模板。拒绝是为了防止这种状态，不是为了省存储。那句误导的提示是「拒绝原因如何上报」
的 bug，已在驱动源码里修正，随下一次 TOD 重编发布。

**要换手指**，先删掉已有的，再录新的：

1. **设置 → 系统 → 用户 → 指纹登录**，用删除控件。
2. 录入你想用的手指。

命令行等价操作：`fprintd-delete 用户名 --finger right-index-finger`。先删再录的顺序随意；
`/var/lib/liuqin-fingerprint/` 里的机器凭据和 Gatekeeper handle 是按账号的，会被复用，
其他东西不需要重建。

**要做到 1:N**，需要两件事：TOD 实现 `identify`，以及 OEM 运行时支持「一次采集匹配多个
数据库」。当前运行时只接受一个（`--match-single DATABASE`），所以这是真实的功能缺口，
不是一个策略开关。

提示语本身已经在驱动源码里修好，并已随当前安装包发布：驱动不再对这种拒绝使用
`FP_DEVICE_ERROR_DATA_FULL`，所以桌面会显示真实原因，而不是「存储已满」。如何在不安装
更新版 dev 包的前提下、对着平板自己的 libfprint 重编 TOD，见
[组件说明](../device/fingerprint/oem/README.md#rebuilding-only-the-tod-when-the-dev-package-would-move-the-abi)。

## 指纹用于 sudo 和 polkit

默认情况下指纹只用于**登录与锁屏**。`sudo`、`pkexec` 以及桌面的特权操作对话框仍然要求
Linux 密码，因为 `pam_fprintd` 只接在 GDM 的 PAM 栈里。

想让已录入的手指满足本机所有 PAM 提示：

```sh
sudo sh device/tweaks/enable-fingerprint-pam.sh           # 启用
sudo sh device/tweaks/enable-fingerprint-pam.sh --dry-run # 先看栈
sudo sh device/tweaks/enable-fingerprint-pam.sh --revert  # 改回仅密码
```

它执行标准的 `pam-auth-update --enable fprintd`，把 `pam_fprintd.so` 放到
`common-auth` 最前面，并带 `default=ignore`。这意味着指纹失败或没有手指时会**落到密码
模块**，所以密码永远仍然可用。改变的是「手指现在可以授权 sudo」——这正是目的，也是对本机
威胁模型的一个决定。`sudo` 和 `polkit-1` 都 include `common-auth`，所以一处改动两者都覆盖。

## 密码和旧身份

密码对话框用于系统 Polkit 授权录入或删除指纹。原生提供程序**不保存 Linux
密码**，而是为指定账号建立独立的、仅 root 可读的随机机器凭据和 Gatekeeper
handle，私有文件留在本机。因此，修改 Linux 密码后，新原生路径无需单独同步
“指纹密码”。

此前由密码派生的旧身份以及已有模板，不会被自动迁移、重建或删除。遇到不确定
创建标记应保留现场，不能靠删除标记重试。首次建立凭据会写入真实 Gatekeeper/
RPMB 状态；若在这段短事务中取消，会先完成安全提交再停止，不继续采集指纹。
临时内核启动不等于这些操作都是只读。

## 验证范围与后续项目

原生录入、模板重载、同指接受、异指拒绝、原生锁屏和正常重启后的 GDM 登录
已通过。现有密码登录继续可用，不需要单独的解锁应用。

日常验证不使用旧流程中仅在本次启动有效的 18 小时录入授权，也不会通过旧助手
索要 Linux 密码。本次重启后直接在正常登录界面验证，没有事先手工运行
Keymaster 协商或设置助手。指纹登录不会解密以密码加密的 GNOME 登录密钥环；
需要访问其中秘密的应用仍可能请求密钥环密码。

接触位置敏感、速度、休眠恢复、长期可靠性、多指/多用户，以及指纹安全存储在
Android 往返后的共存仍未完成验证。

## 附录：恢复和旧调试入口

需要关闭指纹验证、同时保留私有状态和密码登录时，管理员可以停止并屏蔽标准
指纹服务：

~~~sh
sudo systemctl mask --now fprintd.service
~~~

排查时查看 `fprintd.service` 和 `liuqin-fpc-stable-module.service` 的状态及
诊断信息。只共享状态/阶段，不能公开密码、随机凭据、handle、认证令牌、模板
或私有校准。

`acceptance.py`、旧终端启动器和 `user_credentials.py` 仅保留给旧版开发助手
流程内部调试，不是原生用户入口；原生安装会移除它们的应用菜单入口。
旧 `--sync-password` 只适用于此前的密码派生身份。不要把旧版 create 或随机
probe UID 创建当作原生功能的前置检查。两条路径的区别与内核配套要求见
[组件说明](../device/fingerprint/oem/README.md)。
